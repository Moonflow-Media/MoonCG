# Folder structure: MoonCG compared to NodeCG

This document shows the folder structure MoonCG is aiming for and how it differs from NodeCG 2.x.
"Target" means the layout once milestones 0–9 of the plan are done. Parts that do not exist yet
are marked with the milestone that adds them.

There are three different trees to keep apart:

1. **A bundle** — what a bundle author creates.
2. **An installation** — what sits on the machine that runs a show.
3. **The source repository** — the code of MoonCG / NodeCG itself.

## 1. A bundle

### NodeCG

```
my-bundle/
├── package.json          manifest lives in the "nodecg" key, next to npm fields
├── configschema.json     JSON Schema for the bundle config
├── dashboard/            panel and dialog HTML
├── graphics/             graphics HTML
├── extension.js          server code — or extension/index.js, never both
├── schemas/              <replicant name>.json, found by file name
├── shared/               served at /bundles/<name>/shared/
└── node_modules/
```

The bundle's config values live outside the bundle, in `cfg/my-bundle.json` of the installation.

### MoonCG (target)

```
my-bundle/
├── mooncg.json           manifest: own file, with $schema for editor completion
├── config.schema.json    JSON Schema for the bundle config            (milestone 5)
├── dashboard/            panel and dialog HTML
├── graphics/             graphics HTML
├── extension/
│   └── index.js          server code, runs in its own worker thread
├── schemas/              replicant schemas, referenced from mooncg.json
├── shared/               code shared between extension, panels, graphics
├── mooncg-env.d.ts       generated by `mooncg types`
├── package.json          optional, only for npm dependencies
└── node_modules/         optional
```

### Differences

| Topic                              | NodeCG                                                            | MoonCG                                                                                                    |
| ---------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Manifest                           | `"nodecg"` key inside `package.json`                              | Own file `mooncg.json`; `package.json` is optional                                                        |
| Folder name                        | Must equal the package name                                       | Must equal `name` in `mooncg.json`                                                                        |
| Replicants                         | Declared in code by whoever asks first, including browser clients | Declared in `mooncg.json` (default, schema, `persistent`, read/write permission)                          |
| Replicant schemas                  | Found by convention: `schemas/<name>.json`                        | Path stated per replicant in the manifest                                                                 |
| Permissions                        | Not part of a bundle                                              | `permissions` and `defaultRoles` in the manifest; panels, graphics, replicants and messages point at them |
| Extension entry                    | `extension.js` or `extension/index.js`                            | Path stated in the manifest (`"extension": "extension/index.js"`)                                         |
| Where panels and graphics may live | `dashboard/` and `graphics/`                                      | Same, and enforced: files outside these folders are never served                                          |
| Client API                         | Injected into the HTML by the server                              | Imported by the page: `import '/sdk/mooncg.js'` or `@mooncg/sdk/client`                                   |
| Types                              | `nodecg schema-types` writes into `src/types/schemas/`            | `mooncg types` writes `mooncg-env.d.ts`                                                                   |
| Sound cues                         | `soundCues` in the manifest                                       | Not planned for the first version                                                                         |

## 2. An installation

### NodeCG (classic layout)

```
nodecg/
├── bundles/              one folder per bundle, cloned by hand or with the CLI
├── cfg/
│   ├── nodecg.json       server config
│   └── <bundle>.json     bundle config
├── db/
│   └── nodecg.sqlite3    replicants, users, roles, API keys
├── assets/
│   └── <bundle>/<category>/   uploaded files
├── logs/
├── node_modules/
└── package.json
```

NodeCG also supports being installed as a dependency of a single bundle project; then `cfg/`,
`db/`, `logs/` and `assets/` sit in that project's root.

### MoonCG (target)

```
my-show/
├── bundles/              show bundles
│   └── <name>/
├── modules/              system modules (auth providers, storage, …)   (milestone 8)
│   └── <name>/
├── data/                 everything MoonCG writes at runtime
│   ├── mooncg.db         replicants, disabled bundles, users, roles, tokens, sessions (today); layouts (milestone 5)
│   ├── config/
│   │   └── <bundle>.json bundle config                                 (milestone 5)
│   ├── assets/
│   │   └── <bundle>/<category>/                                        (milestone 5)
│   ├── staging/          bundles being installed or updated            (milestone 7)
│   └── backups/          previous version kept for rollback            (milestone 7)
└── mooncg.config.json    server config (port, host, data dir, origins) (file: milestone 6)
```

Today the server is configured with flags and environment variables only (`--bundles-dir`,
`--data-dir`, `--allowed-origin`, …); the config file comes with the CLI's `init` command.

### Differences

| Topic               | NodeCG                                        | MoonCG                                                                                              |
| ------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Runtime data        | Spread over `cfg/`, `db/`, `assets/`, `logs/` | One folder, `data/`. Back up or delete that folder and you have backed up or reset the installation |
| Bundle config       | `cfg/<bundle>.json`, edited by hand           | `data/config/<bundle>.json`, edited in the dashboard as a form generated from the schema            |
| System extensions   | None; one bundle may ship a database adapter  | `modules/`, separate from show bundles and installable only by admins                               |
| Installing a bundle | `git clone` into `bundles/`, then restart     | Through `data/staging/`, validated first, then moved into `bundles/` without a restart              |
| Updating a bundle   | Manual `git pull`, then restart               | Old version kept in `data/backups/` and restored if the new one fails to start                      |
| Logs                | `logs/` files                                 | Console today; a log page in the dashboard with milestone 5                                         |

## 3. The source repository

### NodeCG

```
nodecg/
├── workspaces/
│   ├── nodecg/                          server, Polymer dashboard, client API, types
│   ├── cli/                             @nodecg/cli
│   ├── database-adapter-types/
│   ├── database-adapter-sqlite-legacy/  TypeORM + better-sqlite3
│   └── internal-util/
└── docs/
```

### MoonCG

```
MoonCG/
├── packages/
│   ├── core/         @mooncg/core — pure logic, no file or network access
│   │   └── src/      manifest/ replicant/ messages/ http/ bundle/ protocol/ permissions/ session/
│   ├── server/       @mooncg/server
│   │   ├── src/      kernel/ auth/ bundles/ extension-host/ http/ replicants/ storage/
│   │   └── public/   minimal HTML shell (replaced by the dashboard in milestone 5)
│   ├── sdk/          @mooncg/sdk — the only package bundle authors depend on
│   │   └── src/      client/ extension/ vue/ react/ — later module/ (milestone 8)
│   ├── cli/          the `mooncg` command — `types`, `user` and `token`
│   └── dashboard/    Vue 3 app                                         (milestone 5)
├── examples/
│   └── scoreboard/   reference bundle
├── docs/
└── data/             created on first start, git-ignored
```

### Differences

| Topic                       | NodeCG                                               | MoonCG                                                                                             |
| --------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Split                       | One large package holds server, dashboard and client | Logic without IO (`core`) is separate from the server, so it can be tested without sockets or disk |
| What bundle authors install | `nodecg` (types) plus helper packages                | `@mooncg/sdk` only                                                                                 |
| Database                    | TypeORM adapter packages                             | A small `Db` interface over Node's built-in SQLite, inside `server/src/storage/`                   |
| Dashboard                   | Polymer, inside the main package                     | Own package, Vue 3 + Vite                                                                          |

## URLs, for orientation

The folder names show up in the URLs, so the mapping is worth knowing:

| What               | NodeCG                             | MoonCG                             |
| ------------------ | ---------------------------------- | ---------------------------------- |
| Dashboard          | `/dashboard/`                      | `/`                                |
| Panel              | `/bundles/<name>/dashboard/<file>` | `/b/<name>/dashboard/<file>`       |
| Graphic            | `/bundles/<name>/graphics/<file>`  | `/b/<name>/graphics/<file>`        |
| Bundle HTTP routes | wherever the extension mounts them | `/b/<name>/api/…`                  |
| Assets             | `/assets/<name>/<category>/<file>` | `/b/<name>/assets/…` (milestone 5) |
| Client API script  | injected                           | `/sdk/mooncg.js`                   |
| Sign in, setup     | `/login/` (if enabled)             | `/login`, `/setup`                 |
| Server API         | none                               | `/api/v1/…`                        |
